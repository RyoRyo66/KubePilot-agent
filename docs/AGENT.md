# Agent 实现与验证

更新：2026-11-11。该模块已写入当前 Go / Vue 工程，可以本地运行。

## 实现流程

每个任务限定在配置的命名空间和一个工作负载内，处理其中一个匹配事件。已有巡检继续归集所有故障；定时任务对开启自动策略的新事件创建 Agent 任务。

1. `inspect_cluster`：实际调用当前数据提供器采集最新状态，绑定匹配事件。
2. 模型选择 `read_evidence` 或 `search_runbooks`，读取本次巡检的证据快照和本地知识条目，获得工具反馈后继续选择下一步。
3. `submit_diagnosis` 提交结构化结论、证据编号、建议和限制。必须先读取证据和检索知识，引用必须来自实际已读取的证据。
4. `build_repair_plan` 交给独立执行器生成计划；模型不能指定任意写操作或覆盖动作参数。分析期间对象身份或版本改变则停止。
5. 确认模式保存计划快照与 SHA-256 摘要，确认有效期 15 分钟。提交的摘要必须匹配，执行前再次检查实际计划、对象身份、版本、基线和策略。
6. `execute_and_verify` 复用已有受控修复与业务验证；只有事件实际通过验证才把任务标为 `recovered`。随后重新采集集群状态。

工具定义、参数、调用数量、目标范围和写入权限都由 Go 代码检查，不依赖提示词自行约束。没有 shell / kubectl 任意命令工具，模型不持有执行或确认工具。日志和知识内容只作为证据数据。

## 模型接口

`internal/providers/compatible.go` 使用标准库 HTTP 客户端调用 `<baseURL>/chat/completions`，传递 `messages` 和函数 `tools`。每次只接受一个完整工具调用；将调用及工具结果按 `assistant/tool` 消息反馈给模型。支持保留部分兼容思考模型所需的私有连续上下文，仅在内存中传回服务，不写入运行记录或展示。

协议依据：[DeepSeek API 接入](https://api-docs.deepseek.com/)、[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。兼容接口不意味着所有服务商、模型和思考模式都已实测；需要选择支持函数工具调用的模型。

配置：

```powershell
# 在 kube-agent 目录执行；脚本会隐藏输入密钥并重启本地应用。
.\scripts\start-model.ps1 -BaseURL 'https://api.deepseek.com' -Model '<服务商提供的模型名称>' -SkipBuild
```

也可在启动进程环境中配置：

| 环境变量 | 内容 |
|---|---|
| `AGENT_LLM_BASE_URL` | API 基地址，末尾不包含 `/chat/completions` |
| `AGENT_LLM_MODEL` | 实际模型名称 |
| `AGENT_LLM_API_KEY` | 模型访问密钥；仅服务端使用 |

模型配置优先于 Ollama 单次诊断适配器。没有配置兼容模型时，Agent 使用明确标记的规则编排。配置后发生 401、超时、畸形响应、未知工具、伪造证据或达到工具上限时，任务降级为规则分析并等待人工确认，不继续自动写入。错误记录不保存模型服务响应体或访问密钥。

## 任务与调度

- API 异步返回 `202`，浏览器关闭不会中止任务；服务关闭、显式取消或任务超时会取消执行上下文。
- 一次最多运行一个 Agent worker，同目标的运行中 / 待确认任务去重。不同目标可保留待确认记录。
- 默认最多 8 轮模型工具选择，可配置到 3—16；两次无效工具结果后降级。单个模型请求默认 45 秒，分析和确认后的执行各有 180 秒运行期限。没有自动重试写操作。
- 自动策略关闭时，定时巡检不会产生模型调用。开启后，每个调度周期最多启动一个任务；同事件有 5 分钟调度冷却。
- 保存每个工具的执行意图、参数、实际结果和耗时，以及模型标识、提示词摘要、API 返回的 token 使用量、计划、确认时间和最终状态。
- 本地 JSON 保留最近 100 个任务；只移除已结束任务。重新启动服务时，未结束任务标记为中断，不自动恢复或重放写操作。
- 停止任务不会撤销已经提交的变更；实际恢复与否仍以关联事件和业务验证为准。

知识检索目前是六类排障条目的类型 / 关键词检索，每条返回 ID、内容摘要版本和官方来源。证据工具读取该任务首次巡检采集的快照；没有声称每次调用都新增一次独立日志采集，也尚未接入向量数据库。

## HTTP 接口

所有接口沿用现有 API 令牌和同源写入校验。

| 方法与路径 | 行为 |
|---|---|
| `POST /api/agent/runs` | 创建异步任务；字段：namespace、workload、goal、mode、可选 incidentId / maxSteps |
| `GET /api/agent/runs` | 列出持久化任务 |
| `GET /api/agent/runs/{id}` | 读取任务、步骤、诊断、计划及实际状态 |
| `POST /api/agent/runs/{id}/approve` | 以 `{"planHash":"..."}` 确认展示的具体计划 |
| `POST /api/agent/runs/{id}/cancel` | 以 `{}` 停止后续步骤 |

`mode` 为 `observe`（不写集群资源）、`approval`（确认后执行）或 `automatic`（同时受已启用自动策略控制）。不同模式都不会越过写开关、动作白名单和执行次数限制。

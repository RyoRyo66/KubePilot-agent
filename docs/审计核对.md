# 0.2 审计核对与 0.3 重写说明

核对基线为发布源码提交 `88db50f00eaed56ebb696214ff01f57a68669a21`。报告将安全漏洞、可用性缺陷及架构优化混合计数。下表区分旧源码能支持的结论、成立条件以及新版采取的措施。回归测试使用构造的业务输入，实集群验收覆盖 Service 选择器恢复。

| 报告中的问题 | 对 0.2 的核对结果 | 0.3 的实现或验证边界 |
|---|---|---|
| 模型地址变更、密钥留空 | 成立。保存配置会先取旧密钥，再向本次提交的地址测试连接。需要已登录且有工作空间配置权限。 | 密钥与完整基地址绑定。连接测试成功后再提交，提交前重新核对会话和旧配置。 |
| 模型与健康检查出站地址 | 部分成立。旧兼容模型已禁止重定向，仍缺解析后目标 IP 校验。Ollama 地址由部署者配置。业务探测确实需要访问集群内部。 | 公网模型在拨号前验证并绑定解析结果。自托管模型由管理员登记。集群业务检查按授权地址和命名空间的 Service ClusterIP 核对，拒绝元数据和链路本地地址。 |
| 取消、待审批过期、只读进入等待 | 成立。取消与工作线程退出之间存在窗口，过期原本只在用户点击确认时处理。正常终态也有保护，并非每次取消都会卡住。 | 单机执行队列、取消信号、审批到期处理与只读任务路径重新实现。平台审批在执行前另行检查期限、计划和资源。 |
| 平台停机、Connector 上报 | 成立。旧平台遍历服务表与新建空间可能并发，HTTP 停机与释放锁的顺序不可靠。已取消的上下文也可能阻止回传结果。 | 平台先停止接单，等待任务和 HTTP 请求结束后释放存储。Connector 独立保存写入记录与待回传结果，回传使用独立时限。写入结果不确定时转人工核查。 |
| Connector 类型断言及并发 Map | 旧源码存在未检查的类型断言，但默认构造器选择的具体类型相符，原轮询主循环串行。报告未给出正常调用中发生 panic 的证据。 | 新版显式传入采集适配器，写入尝试使用 SQLite 唯一键登记。 |
| 深拷贝吞错、掉电持久性 | 忽略序列化错误属实。日常输入足以造成整库覆盖的判断缺少证据。 | SQLite 事务、WAL 与 FULL 同步，密文绑定工作空间、记录类型和主键。旧库导入到新目录，解密或校验失败不会覆盖原库。 |
| 模型字段注入、诊断截断、检索标志 | 诊断入参比工具声明宽，旧代码从截断用的展示结果反解业务对象，检索命中标志也可能被后续零结果覆盖。默认模型适配器另有参数大小限制，报告未证明 96 KiB 路径可由它触发。 | 限定工具、允许字段和取值，逐条验证证据编号。复核结果须绑定计划哈希。业务对象直接取自已校验结果。 |
| 限流与匿名接入的成本 | 未认证机器请求逐空间比对并深拷贝，反代共用对端地址属实。单一来源只靠随机用户名就能填满所有桶的结论忽略了前置 IP 限流。旧单机拒绝审计发生在 API 鉴权之后。 | 机器令牌摘要索引查找。登录限流采用定长槽，密码计算限制并发。仅信任管理员配置的反代对端及其覆盖的客户端地址。 |
| 心跳写盘、轮询冻结、队列等待 | 心跳重复全量写盘属实。手工事件验证的提前退出可能造成饥饿。旧版每轮处理一个 new 事件影响吞吐，但不能据此推断所有后续事件永久阻塞。 | 心跳保存在内存，租约和结果以带时限的 Promise 交付。每个空间串行执行，扫描轮换起点；重启丢弃旧租约，保留已登记写入。 |
| 全量 Update 与 HPA 冲突 | 旧代码提交整个对象，确实需要 update 权限。已有 resourceVersion 约束，不能据此断言必然覆盖 HPA 的修改。 | Role 按资源名授予 patch；Connector 在 JSON Patch 内测试 UID、版本和容器名，先 dry-run，后提交允许的字段。RBAC 自身没有字段级权限。 |
| 初始容器、事件时间、日志、命名空间 | 旧主采集路径存在这些遗漏。Pod exit code 及 Unhealthy 事件分别不足以单独证明 OOM 或探针配置错误。 | 同时读取初始容器和常规容器状态，使用事件序列最近时间，优先保留明确的退出状态；取不到上次日志时再取当前日志。限制 log 返回大小，不能保证包含所有历史记录。 |
| 重试已恢复事件、失效计划、中文告警摘要 | 旧代码在这些边界的处理不足。 | 终态和已登记写入的事件禁止重试。新检查结果需匹配资源身份。告警摘要按 Unicode 字符限制长度。 |
| 默认开放注册、模型重试、journal 清理 | 注册是部署选择；对模型 429 自动重试、数据库选型和组件拆分属于可靠性或设计取舍。对结果不确定的集群写操作自动重放会增加风险。 | 可关闭注册。模型输出未通过验证时停止自动处置。Connector 执行记录随持久卷保存，归档属于管理员运维事项。 |
| 监控、容器权限、健康探针 | 旧实验模板中的问题成立。旧生产平台 Compose 已有只读文件系统与 capability 限制。 | 重写的监控模板不启用生命周期管理接口，存活探针与就绪探针分开。平台、Connector 和测试业务以非 root 身份运行。 |
| 前端请求超时、过期轮询、跨页签刷新、组件卸载 | 部分属实。旧平台请求无超时，写操作后的刷新可能被跳过，独立页面有异步挂载后创建定时器的窗口。sessionStorage 本身不能证明服务端明文存储用户密码。 | 按指定范围保留 39 个前端文件。服务端时限能限制后端工作，浏览器断网、轮询时序和未保存表单等行为仍需单独修改前端。 |

本次没有复现外部攻击，也没有对公网或云上的账号、工作空间进行测试。回归通过和实集群验收均有具体场景范围，不能替代独立安全审计或压力测试。

## 0.3.1 复查

| 范围 | 源码核对与修复 |
| --- | --- |
| 登录与模型接入 | 登录频率按来源地址和账号组合计数。限流表使用完整键并限制容量，密码计算先检查全局与来源并发。模型连接测试另设工作空间并发和频率限制。共享出口的用户仍共用来源预算。 |
| Connector 调度 | 长轮询有任务时立即唤醒。心跳独立于采集、执行和验证。平台只接受与现有租约、代次、执行端及期限一致的结果并续期。执行租约截止时间取任务期限和复核期限的较早值。 |
| 事件与存储 | 拒绝写入的事件可只读核验外部恢复。新授权优先回收旧代次记录，同代活动事件满额时仍保存快照。SQLite 支持嵌套保存点，按更新时间淘汰，并为会话及活跃度建立索引。 |
| 集群访问与证据 | 外置 kubeconfig 客户端按 API 组、命名空间、资源、子资源和参数校验。旧接口由内部采集代码调用；仅凭旧校验形式无法证明它对外暴露。集群探针的私网地址须与实时 Service 或显式登记的目标 IP 一致。优先采集故障 Pod 和活跃控制器的事件，保留最近日志，处理表达式选择器与初始容器。 |
| 基线与写入 | 连续健康采样确认新基线，预检成功后在提交前持久登记。已知预检失败可以重新诊断。提交结果未知时保留写入记录。过期事件不能通过回收记录重新执行。 |
| 模型与单机实验台 | 工具调用仍须与指定工具、字段和证据编号匹配。限制请求规模并对临时响应做有限重试。单机确认使用页面所示计划摘要和有效期，基于新证据继续补采；限制运行历史和事件时间线。 |
| 浏览器与部署 | 账号请求设置超时，配置写入使旧轮询响应失效，页面卸载时终止安装定时器。Compose 默认关闭注册。Connector 镜像单独构建，配置就绪和存活探针；构建基础镜像和监控镜像固定摘要。监控配置采用结构化序列化，导入失败清理本次临时目录。 |

启动本地回归使用 `npm test`。实集群验收覆盖 Service 选择器修复和人工审批，Deployment 镜像、探针及初始容器的覆盖来自自动化测试。测试用模型具备确定性，应另行评估线上模型诊断质量。
